PageScout Privacy Policy

Effective October 7, 2026

Privacy Policy for the PageScout Chrome extension.

Who processes the data

The operator is Paul Tagankin, an individual and the extension's developer (teamspeed339@gmail.com). This policy covers data handling by the PageScout extension itself. Data handling on the side of the LLM provider you choose is governed by that provider's policy.

What data the extension handles

1. LLM connection settings (entered by you). API token, API base URL, and model name. Stored locally on your device in chrome.storage.local. These are the only data the extension ever writes to disk.

2. Chat messages and tool results. Your prompts, the model's replies, and tool execution results — including current-page content obtained by tools. Processed in panel memory within a session: never written to disk, never retained after the panel closes, never sent to the developer.

3. Page tool metadata. Names, descriptions, and schemas of the WebMCP tools a page publishes itself. Read to display the tool list and included in requests to your LLM endpoint (see below).

4. Local activity log. Technical session events (discovery, confirmations, errors) — in panel memory only, capped at 200 entries, with no chat content, tool arguments, or keys.

What is transmitted, and to whom

The only network destination is the LLM endpoint you configure. On each of your requests to the assistant, the extension sends to that address: the chat messages, tool metadata and results, and your API token in the Authorization header. The endpoint must use HTTPS (exception: localhost/127.0.0.1 for local debugging). No data is transmitted to the developer. Clarification: the extension itself contacts only this address; the page's own tools and the JavaScript you approve run in the page's context and may contact that page's own services — as if you ran them on the page manually.

What the extension does not do

  • No telemetry, analytics, or advertising data; no third-party trackers.
  • No servers of its own for processing chats; data is never sold or shared with third parties other than the endpoint you specify.
  • Does not read browsing history, passwords, or payment data.
  • Does not load remote code or execute it in the extension's context. The only exception is JavaScript generated by your LLM and run on the page after your explicit one-time approval (see "Executing JavaScript on the page").

Executing JavaScript on the page (evaluate_script)

The built-in evaluate_script tool runs JavaScript in the context of the current page only after your explicit one-time approval: the confirmation card shows the complete function source and its arguments. The browser debugger is attached for the duration of that single approved call and is detached immediately afterwards — regardless of outcome. Approval cannot be granted "forever": it works once and is bound to the exact page, tool set, and arguments.

Storage and deletion

  • Connection settings are kept until you change them or remove the extension's data in Chrome (the panel has no separate clear button — settings can be overwritten, or deleted only together with the extension's data).
  • Chat and activity log exist only in session memory and disappear when the panel closes.

User rights

You can review and change the settings in the panel at any time, or remove the extension entirely — along with all its local data.
